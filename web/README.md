# web

The TrevStack web app is a [SolidJS](https://www.solidjs.com/) single-page app that talks to the
server's ConnectRPC API. It is built with [Vite](https://vite.dev/), styled with
[Tailwind CSS](https://tailwindcss.com/) and [Catppuccin](https://catppuccin.com/), and installable
as a progressive web app.

The production build is embedded in and served by the [server](../server/README.md), so there is
nothing to deploy separately.

## pages

| path       | description                                             |
| ---------- | ------------------------------------------------------- |
| `/auth`    | sign in and sign up                                     |
| `/`        | add a named number                                      |
| `/numbers` | filter and browse recorded numbers as they stream in    |
| `/metrics` | summary, time series, distribution, and top name charts |

Every page except `/auth` requires a session; signed-out visitors are redirected to `/auth` and
returned to the page they asked for after signing in. RPCs that fail with `permission_denied` show
`/403`.

## api

RPCs are sent to `/grpc` on the same origin using the Connect protocol, as JSON in development and
binary protobuf in production. Clients for each service are in [`lib/connect`](lib/connect) and
wrap calls in [Effect](https://effect.website/) for typed errors and cancellation.

The session itself is the server's `HttpOnly` `stack_session` cookie, which the browser sends
automatically. The app keeps only the username and expiry in local storage so it can tell, without
a request, whether to show signed-in pages. It signs out when the session expires or when an RPC
fails with `unauthenticated`, and syncs sign-in state across tabs.

## progressive web app

A service worker caches the app shell for offline use; `/grpc` and `/docs` are never served from the cache.
The app checks for a new version every 15 minutes and whenever it comes back into view,
then offers the update in a toast instead of reloading, so unsaved input is never lost.

## development

Start the server in another terminal (see [server development](../server/README.md#development)),
then, inside the development shell, from this directory:

```sh
npm install
npm run dev
```

The app is served at http://localhost:3000 with hot reloading.
`/grpc` and `/docs` are proxied to the server at `localhost:8080`.

| command         | description                                 |
| --------------- | ------------------------------------------- |
| `npm run dev`   | start the development server                |
| `npm run build` | build the production app into `dist/`       |
| `npm run serve` | preview the production build                |
| `npm test`      | run the [Vitest](https://vitest.dev/) tests |

Formatting and linting use [oxfmt](https://oxc.rs/docs/guide/usage/formatter) and
[oxlint](https://oxc.rs/docs/guide/usage/linter); both run in `nix flake check`.

### layout

| path        | description                                                  |
| ----------- | ------------------------------------------------------------ |
| `index.tsx` | entry point, routes, and session gating                      |
| `index.css` | Tailwind and theme setup                                     |
| `routes/`   | one directory per page                                       |
| `layout/`   | navigation bar, user menu, theme switch, and network status  |
| `lib/`      | shared components, auth, Connect clients, and Effect helpers |
| `connect/`  | code generated by `buf generate`; do not edit                |
| `public/`   | static files copied into the build as-is                     |

Import shared code with the `$lib/*` alias and generated code with `$connect/*`.
