# client

The TrevStack client is a Rust command-line tool that records a named number on the server and
prints the new total. It talks to the server over gRPC using [tonic](https://github.com/hyperium/tonic).

## usage

```sh
STACK_PASSWORD=example-password \
  client --username demo_user alice 10
```

The client logs in, sends `alice` and `10` to `NumberService.Add`, then prints the sum of every
number stored on the server.

### arguments

| argument | description                             |
| -------- | --------------------------------------- |
| `NAME`   | name associated with the number         |
| `NUMBER` | number to add, from `0` to `4294967295` |

### options

| flag                  | environment      | default                      | description                    |
| --------------------- | ---------------- | ---------------------------- | ------------------------------ |
| `--url URL`           | `STACK_URL`      | `http://127.0.0.1:8080/grpc` | server API base URL            |
| `--username USERNAME` | `STACK_USERNAME` |                              | **required**, account username |
| `--password PASSWORD` | `STACK_PASSWORD` |                              | **required**, account password |
| `-h, --help`          |                  |                              | print help                     |
| `-V, --version`       |                  |                              | print version                  |

Flags take precedence over environment variables. Prefer `STACK_PASSWORD` over `--password` to keep
the password out of the process list and shell history.

The URL must use `http` or `https` and may include a path prefix such as `/grpc`, but not
credentials, a query string, or a fragment. `https` URLs are verified against the bundled
[webpki roots](https://github.com/rustls/webpki-roots).

### authentication

The account must already exist; create one from the web app or with `AuthService.Signup`. The
client calls `AuthService.Login` and sends the returned token as the `stack_session` cookie on
`Add`. The token is not stored between runs.

### exit status

The client exits `0` and prints the sum to stdout on success. On failure it prints an error to
stderr and exits `1`, or `2` when the arguments cannot be parsed. Connecting times out after 5 seconds and each
request after 10 seconds.

## development

From the repository root, run the client with:

```sh
STACK_USERNAME=demo_user STACK_PASSWORD=example-password \
  nix run .#client -- alice 10
```

or, inside the development shell, from this directory:

```sh
STACK_USERNAME=demo_user STACK_PASSWORD=example-password \
  cargo run -- alice 10
cargo test
cargo clippy --all-targets
```

### layout

| path            | description                                   |
| --------------- | --------------------------------------------- |
| `src/main.rs`   | entry point                                   |
| `src/cli.rs`    | argument and environment parsing              |
| `src/client.rs` | URL validation, login, and the `Add` call     |
| `src/proto.rs`  | module wrapper for the generated code         |
| `src/connect/`  | code generated by `buf generate`; do not edit |
